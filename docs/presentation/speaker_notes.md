# АгроВижн — сценарий защиты

Рекомендуемое время: 7–9 минут на презентацию и 3 минуты на живое демо.

## 1. Титульный слайд — 20 секунд

«АгроВижн — end-to-end система, которая считает овец на аэросъёмке и превращает
результат модели в понятный рабочий интерфейс. Она принимает живые и записанные
потоки, фото и видео, показывает динамику и сохраняет результаты в базе».

## 2. Задача — 30 секунд

Объяснить цепочку: источник даёт кадр, модель находит животных, оператор получает
число голов и историю наблюдений. Главная ценность — один воспроизводимый процесс
вместо ручного пересчёта и набора разрозненных скриптов.

## 3. Четыре сценария — 35 секунд

Перечислить только реализованные сценарии: два локальных облёта, подключаемый RTSP,
разовая загрузка фото/видео, журнал и экспорт отчётов. Подчеркнуть, что интерфейс
полностью на русском и готов к автономной демонстрации.

## 4. Главный экран — 35 секунд

Показать три уровня информации: общий счёт и состояние потоков, сведения о модели и
устройстве, операционный порог. Версия checkpoint и устройство исполнения видны
оператору, поэтому результат можно связать с конкретной моделью.

## 5. Видео и RTSP — 55 секунд

Запустить встроенный ролик кликом по кадру: это фактический аннотированный результат
для `7438342-uhd_4096_1974_30fps.mp4`, пик — около 1.2 секунды. Ролик H.264 длится
6.7 секунды и хранится внутри PPTX, поэтому для воспроизведения не нужен внешний файл.

Два ролика с дрона идут параллельно. Для реальной камеры оператор задаёт название,
местоположение и RTSP URI. URI используется только backend и не возвращается в API.
При разрыве источник автоматически пытается восстановить соединение.

## 6. Порог — 30 секунд

Порог 0.40 определяет уверенный итоговый счёт. Его изменение применяется ко всем
источникам без перезапуска модели. Детекции ниже порога не скрываются: они остаются
оранжевыми, чтобы оператор видел неопределённость.

## 7. Разовый анализ — 35 секунд

Показать загрузку фото и видео, затем реальные аннотированные кадры. Сервер проверяет
тип, размер и число пикселей, отправляет задачу в общую очередь и сохраняет сессию.
Результат содержит счёт, рамки, уверенность, время и версию модели.

## 8. Метрики — 45 секунд

На контрольной выборке: precision 95.8%, recall 93.4%, mAP@50 96.3%, mAP@50–95
56.8%. Для подсчёта MAE 6.28 головы и RMSE 11.39. Не выдавать эти числа за полевую
гарантию: ограничение split честно показано на последнем слайде.

## 9. ML-конвейер — 40 секунд

Датасет Aerial Sheep v1 получен из Roboflow и имеет Public Domain license. YOLO26n
обучалась на MPS с фиксированным seed; выбран лучший checkpoint эпохи 10. Веса
весят около 20 MB. При старте приложение проверяет полный SHA-256 и завершает запуск,
если файл отсутствует или изменён.

## 10. Архитектура — 40 секунд

Это модульный монолит с гексагональными слоями. Домен не импортирует FastAPI,
SQLAlchemy или PyTorch. Детектор, хранилище и источник потока подключаются через
порты. Поэтому RTSP заменил файловый источник без изменения бизнес-логики.

## 11. Runtime — 35 секунд

PyTorch синхронный, поэтому его нельзя выполнять внутри asyncio event loop. Все
HTTP-запросы и потоки используют bounded queue; один worker выполняет инференс вне
event loop и не допускает конкурентного обращения к одному экземпляру модели.
Локально Apple Silicon использует MPS, Docker-контейнер Linux — CPU.

## 12. Стек — 30 секунд

Назвать связки по назначению: Python/YOLO/OpenCV для CV, FastAPI/Pydantic/SQLAlchemy
для контрактов и данных, React/TypeScript/Tailwind/Recharts для UI, Docker/Nginx/
PostgreSQL для полного окружения. Версии Python зафиксированы в `uv.lock`, frontend —
в `package-lock.json`.

## 13. Docker и PostgreSQL — 45 секунд

Команда `make docker-up` запускает PostgreSQL 16, API и web. Healthcheck базы
разрешает старт API, затем web. Модель, оба дрон-видео и демонстрационные результаты
монтируются read-only; uploads и БД используют volumes. API работает от uid 10001.
Порты PostgreSQL и API доступны только через loopback хоста.

## 14. Безопасность и секреты — 55 секунд

В локальной среде секреты находятся только в `.env`: файл исключён из Git и имеет
права `0600`. Compose требует `JWT_SECRET` и `POSTGRES_PASSWORD` и не запускается без
них; значения не встраиваются в Docker image и не выводятся в презентации или логах.
Пароли хэшируются Argon2, доступ защищён JWT, checkpoint проверяется по SHA-256,
uploads ограничены, контейнер non-root, mounts read-only.

Честно назвать следующий production hardening: TLS, внешний secret manager,
HttpOnly SameSite cookies вместо frontend localStorage, полностью внутренний порт
PostgreSQL и allowlist сетей для RTSP.

## 15. Финал — 35 секунд

Система уже проходит полный сценарий от видеокадра до отчёта. Ограничение текущей
оценки: соседние кадры исходных DJI-видео попали в разные train/validation/test splits,
поэтому test-метрики оптимистичны. Следующий технический шаг — split по полётам,
полевой набор и сравнение с ручным пересчётом.

## Живое демо — 3 минуты

1. Открыть `http://localhost:5173` и войти демо-пользователем.
2. На обзорном экране показать устройство MPS, модель, SHA и два потока.
3. Передвинуть порог и применить ко всем потокам.
4. Прокрутить до RTSP-формы, объяснить server-side хранение URI; реальный адрес не
   вводить, если камера не подготовлена.
5. Открыть «Анализ», загрузить небольшой тестовый кадр и показать результат.
6. Открыть «Примеры», затем «Отчёты» и экспорт CSV/PDF.

## Резервные ответы жюри

- **Почему YOLO26n n?** Компактная модель подходит для интерактивного прототипа и
  оставляет путь к edge-развёртыванию; фактическое качество фиксируется метриками.
- **Почему PostgreSQL?** Пользователи, сессии и отчёты требуют транзакционного
  хранилища; SQLite остаётся удобным режимом автономного локального демо.
- **Что произойдёт под нагрузкой?** Bounded queue создаёт backpressure и защищает
  модель и память. Горизонтальное масштабирование можно делать по экземплярам API.
- **Можно ли доверять числу?** Это визуальная оценка с отображением неопределённости,
  а не инвентаризационная гарантия. Для production нужен flight-level test set.
- **Где ключ Roboflow?** Он нужен только на этапе получения датасета. В runtime
  приложения ключ не требуется и в репозитории не хранится.
